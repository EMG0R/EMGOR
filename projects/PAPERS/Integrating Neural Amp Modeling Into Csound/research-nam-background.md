# Background Research: Neural Amp Modeler (NAM) for Csound-Community Readers

*Research compiled 2026-07-03 for ICSC 2026 paper background/related-work sections. This document is for context only — it is not a specification for reimplementing NAM's training pipeline or DSP code. Every claim below is sourced inline; items that could not be independently verified are flagged explicitly rather than asserted.*

## 1. What NAM Is

### 1.1 Origin and creator

NAM ("Neural Amp Modeler") was created by **Steven Atkinson**, GitHub handle **`sdatkinson`**, confirmed via his GitHub profile and as sole author/copyright holder across the ecosystem's repos [sdatkinson (Steven Atkinson) · GitHub](https://github.com/sdatkinson). In his own account, NAM began as "a kind of fun side project while I was getting deeper into machine learning," combining his musician background with ML work. He frames the project's goal around authenticity of personal gear ("if you love how your amp chugs, you literally record yourself chugging, and now that sound is yours forever") and long-term sustainability through open source ("if I stopped working on it tomorrow, the code is out there") [AI and the Future of Guitar Tone: Steven Atkinson Interview, TONE3000](https://www.tone3000.com/blog/ai-guitar-tone-interview-neural-amp-modeler-inventor-steven-atkinson). Interview material places the project's origin around 2018–2019.

### 1.2 Repository / ecosystem layout

NAM is split across a layered set of repositories, a structure the project itself documents on its official site:

- **[`sdatkinson/neural-amp-modeler`](https://github.com/sdatkinson/neural-amp-modeler)** — the Python training repo ("Neural network emulator for guitar amplifiers," MIT license, ~2.8k GitHub stars at time of research). Handles training and export of `.nam` model files; documentation lives at [neural-amp-modeler.readthedocs.io](https://neural-amp-modeler.readthedocs.io/en/latest/tutorials/full.html).
- **[`sdatkinson/NeuralAmpModelerCore`](https://github.com/sdatkinson/NeuralAmpModelerCore)** — "Core DSP library for NAM plugins," the C++ real-time inference engine, built on Eigen for linear algebra; ships a `benchmodel` tool for real-time performance benchmarking.
- **[`sdatkinson/NeuralAmpModelerPlugin`](https://github.com/sdatkinson/NeuralAmpModelerPlugin)** — the official plugin, built with **iPlug2**. As of this research it ships **VST3 and Audio Unit (AU)** builds plus a standalone desktop app; the README lists AAX, CLAP, Linux, and iOS as *possible future targets*, i.e. not currently shipped by the official build. MIT licensed; supports Windows 10+ and macOS 10.15+.
- The project's own "the code" page confirms this three-repo layering — Trainer → Core DSP → Plugin — as the intended architecture [The code | Neural Amp Modeler](https://www.neuralampmodeler.com/the-code).
- Linux users are directed to a **separate, third-party LV2 plugin**, [`mikeoliphant/neural-amp-modeler-lv2`](https://github.com/mikeoliphant/neural-amp-modeler-lv2), which is *not* maintained by Atkinson himself. This distinction matters for the paper: the "official" plugin's format coverage is VST3/AU only; LV2 support is community-maintained and separate.
- The `.nam` model file is a **JSON format**. Documented fields include `version`, `name`, `gear_type`, `tone_type`, `architecture` (typically `"WaveNet"` or `"LSTM"`), an architecture-specific `config` object, and a flat `weights` array [.nam file specification](https://neural-amp-modeler.readthedocs.io/en/latest/model-file.html).

### 1.3 DSP / neural architectures

NAM supports multiple interchangeable architectures, selected per model via the `architecture` field in the `.nam` file:

- **WaveNet-style dilated causal convolutional network.** Confirmed as one of NAM's core architectures by NeuralAmpModelerCore's own documentation. A single dilated conv layer's receptive field is `(kernel_size − 1) × dilation + 1`; layers are stacked and configured via `LayerArrayParams` (an example shipped model, "A2," uses 23 layers with LeakyReLU activation). Gated variants split channels into a tanh-activated "input" path and a sigmoid-activated "gating" path multiplied element-wise — the classic WaveNet gating mechanism [WaveNet Architecture | DeepWiki (NeuralAmpModelerCore)](https://deepwiki.com/sdatkinson/NeuralAmpModelerCore/2.3.1-wavenet-architecture). This traces architecturally to the original WaveNet paper: van den Oord et al., **"WaveNet: A Generative Model for Raw Audio,"** arXiv:1609.03499 (DeepMind, Sept. 2016) [arXiv](https://arxiv.org/abs/1609.03499), adapted into a non-autoregressive, feedforward variant for real-time regression rather than autoregressive generation — the same adaptation pioneered for amp modeling in the Aalto University literature discussed in Section 3.
- **LSTM-based models.** Confirmed as an alternative architecture, both in the `.nam` spec (`architecture: "LSTM"`) and in the training repo's source, `nam/models/recurrent.py` [recurrent.py](https://github.com/sdatkinson/neural-amp-modeler/blob/main/nam/models/recurrent.py).
- A third **ConvNet** architecture is also referenced in DeepWiki documentation, though it is less thoroughly documented than WaveNet/LSTM; whether it is materially distinct or a simplified WaveNet variant was not independently confirmed.
- **Slimmable network / "SlimmableContainer" concept — confirmed and NAM-specific.** Atkinson published **"Slimmable NAM: Neural Amp Models with adjustable runtime computational cost,"** arXiv:2511.07470 (submitted Nov. 8, 2025) [arXiv:2511.07470](https://arxiv.org/abs/2511.07470). The technique lets a single trained model's width (channel count) be scaled down at inference time with no retraining and negligible overhead, trading modeling fidelity against CPU cost — relevant for embedded/pedal hardware versus desktop DAW use. A companion blog post frames this as "the future of Neural Amp Modeler" for adjustable quality/CPU tradeoffs [Slimmable NAM blog, TONE3000](https://www.tone3000.com/blog/slimmable-nam-the-future-of-neural-amp-modeler). NeuralAmpModelerCore's own docs corroborate that its WaveNet implementation supports "dynamic runtime channel reduction" [DeepWiki WaveNet page](https://deepwiki.com/sdatkinson/NeuralAmpModelerCore/2.3.1-wavenet-architecture). **This directly supports the paper's framing that NAM already has a built-in notion of tunable computational cost — relevant to justifying a Csound opcode with adjustable quality/performance settings.**

### 1.4 Academic publication record specific to NAM

The only confirmed Atkinson-authored academic paper specifically about NAM is the Slimmable NAM arXiv paper above (arXiv:2511.07470). No AES paper by Atkinson describing NAM's core architecture was found in this research. Note for citation hygiene: **"End-to-End Amp Modeling: From Data to Controllable Guitar Amplifier Models"** (arXiv:2403.08559) is a *Neural DSP* paper (Juvela, Damskägg, Peussa, et al.), **not** by Atkinson, and should not be cited as a NAM paper despite topical overlap [End-to-End Amp Modeling abstract](https://arxiv.org/abs/2403.08559).

## 2. How NAM Models Are Trained (Reamping / Capture Workflow)

*Presented here as conceptual background for readers unfamiliar with the ML-audio training loop — not as a replication guide.*

### 2.1 The reamping/capture workflow

NAM's own documentation states that paired input/output training audio is obtained "either by reamping a pre-recorded test signal or by simultaneously recording your DI and the effected tone" [Training locally with the full-featured NAM](https://neural-amp-modeler.readthedocs.io/en/latest/tutorials/full.html), [sdatkinson/neural-amp-modeler](https://github.com/sdatkinson/neural-amp-modeler). In plain terms: a known reference audio signal is played back through the real physical device under capture (amp, pedal, preamp, etc.), the device's output is recorded, and a neural network is then trained via supervised learning to reproduce the output from the input. Community tutorials describe the physical signal chain in detail: audio interface output → reamp box → amplifier → microphone or load box → audio interface input, with strict requirements that the recorded render match the input file's length "down to the sample," at 48kHz/24-bit/mono, with no clipping, and all onboard effects (chorus, delay, reverb, compression) disabled so that only the target device's characteristic is captured [Nail The Mix: Capturing Your Own Amps with NAM](https://www.nailthemix.com/the-producers-guide-to-capturing-your-own-amps-with-nam).

### 2.2 The standard reference training input signal

NAM uses a specific, versioned reference input file rather than arbitrary audio — this was confirmed via NAM's own GitHub issue tracker. The file has gone through several versions: `v1_1_1.wav`, then `v2_0_0.wav`, then `v3_0_0.wav`; GitHub issue #443 documents that `v3_0_0.wav` was subsequently renamed to the simpler `input.wav` as the standardized filename going forward [GitHub Issue #443: Rename v3_0_0.wav to input.wav](https://github.com/sdatkinson/neural-amp-modeler/issues/443), and the file is distributed from NAM's own Colab training notebook [NAMTrainerColab repo](https://github.com/sdatkinson/NAMTrainerColab/blob/main/notebook.ipynb). It is described qualitatively — by NAM's own Colab documentation and by community guides — as a designed excitation signal comprising "a series of sweeps and noises" engineered to excite the target device across its frequency range and dynamic (gain) range [readthedocs Colab tutorial](https://neural-amp-modeler.readthedocs.io/en/latest/tutorials/colab.html), [Nail The Mix: A Guide to Neural Amp Modeler](https://www.nailthemix.com/a-guide-to-neural-amp-modeler-nam). **Not independently verified**: the file's exact duration or internal sweep/noise design (e.g., whether it uses swept sines, chirps, or noise bursts) — sources describe it only qualitatively.

### 2.3 Loss functions: ESR and pre-emphasis filtering

Confirmed directly from NAM's source code (`nam/models/losses.py`): NAM implements an `apply_pre_emphasis_filter` function — a first-order high-pass filter of the form `x[n] − coef·x[n−1]` — and an **Error-to-Signal Ratio (ESR)** function computing `mean((pred − target)²) / mean(target²)` [losses.py source](https://github.com/sdatkinson/neural-amp-modeler/blob/main/nam/models/losses.py). This traces to prior academic literature: Wright & Välimäki's **"Perceptual Loss Function for Neural Modelling of Audio Systems"** (arXiv:1911.08922) defines ESR as `Σ(y−ŷ)² / Σ(y²)` with a pre-emphasis filter `H(z) = 1 − αz⁻¹` (typical `α ≈ 0.85–0.95`) that upweights high-frequency error to better match perceptual sensitivity [Perceptual Loss Function paper (arXiv:1911.08922)](https://arxiv.org/pdf/1911.08922). NAM's own GitHub issue #10 explicitly requests implementing this "Wright et al. 2020" ESR metric as a validation loss, directly cross-referencing the academic source [NAM GitHub Issue #10: ESR metric](https://github.com/sdatkinson/neural-amp-modeler/issues/10). `losses.py` also includes a multi-resolution STFT loss (MRSTFT, via the `auraloss` package) and an MSE-FFT variant, used particularly for cabinet/impulse-response fitting. **Not independently verified**: which loss NAM's trainer uses by default (pre-emphasized ESR vs. plain ESR/MSE) — the pre-emphasis function exists in the codebase but the default configuration was not confirmed.

### 2.4 Training data/time requirements

No official NAM specification pins down a minimum amount of raw audio required — the standard reference files are fixed-length, and community sources describe them only as "an exact number of seconds long" for DAW render alignment. Community-reported, non-official figures: NAM's own Colab tutorial documentation describes the one-click trainer as finishing "in about 10 minutes" [readthedocs Colab tutorial](https://neural-amp-modeler.readthedocs.io/en/latest/tutorials/colab.html); community guides cite 15–20 minutes as more typical in practice [Nail The Mix guide](https://www.nailthemix.com/the-producers-guide-to-capturing-your-own-amps-with-nam). Forum/blog estimates suggest roughly 100 training epochs as a reasonable starting point (~15–20 minutes on a Colab GPU or a consumer GPU such as a GTX 1070-class card), with more complex tones sometimes trained for 400–600 epochs and diminishing returns reported beyond roughly 1000; one reported run reached ESR ≈ 0.010 after 150 epochs in about 20 minutes [S3 Sound: How to Optimize NAM Training](https://s3sound.com/blog/how-to-neural-amp-modeler-training), [Gearspace NAM training thread](https://gearspace.com/board/music-computers/1446503-nam-model-training-thread-neural-amp-modeler.html). This separate literature-derived figure is also relevant: the Wright et al. 2020 journal paper (see Section 3) reports that **roughly 3 minutes of training audio** was sufficient for their WaveNet/RNN black-box models of guitar amps and pedals [Real-Time Guitar Amplifier Emulation with Deep Learning, MDPI Applied Sciences](https://www.mdpi.com/2076-3417/10/3/766) — broadly consistent with NAM's own short reference-file approach, though NAM's exact default file length was not independently confirmed.

### 2.5 Generality beyond guitar amps

NAM's own site and third-party guides explicitly frame the technique as general-purpose black-box modeling, not limited to guitar amplifiers: NAM is described as usable for "guitar amplifiers, bass amps, effects pedals, preamps, outboard gear and complete signal chains," using deep temporal convolutional/recurrent networks trained on real-gear recordings rather than circuit-level modeling [Neural Amp Modeler official site](https://www.neuralampmodeler.com/), [TONE3000 NAM guide](https://www.tone3000.com/guides/neural-amp-modeler). The `.nam` file's own metadata schema includes a `gear_type` field for categorizing captured hardware (amp vs. pedal, etc.), which is itself evidence that the project's own data model treats "amp" as one case among several supported gear types [readthedocs Colab tutorial](https://neural-amp-modeler.readthedocs.io/en/latest/tutorials/colab.html).

A caveat, also stated explicitly in project sources: NAM's black-box approach works best on devices that are **quasi-time-invariant nonlinear systems**. Strongly time-based or dynamics-heavy effects — delay, and reportedly compressors — are harder to capture well with the standard approach. NAM's announced next-generation "A2" architecture is specifically aimed at improving capture quality for dynamics-heavy gear such as compressors [TONE3000: Announcing A2](https://www.tone3000.com/blog/a2-next-generation-neural-amp-modeler). This nuance is useful for the paper: it supports the "generalizes to almost any nonlinear audio system" framing while being honest about where the black-box reamping approach is weaker (strongly time-varying or long-memory effects).

## 3. Key Academic Lineage

This is the real, verified academic lineage underlying NAM's approach — useful for a "related work" section establishing that NAM sits within an established line of DSP/ML research rather than being a novel architecture in itself.

### 3.1 WaveNet-based guitar/distortion modeling (Aalto University group)

- Damskägg, E.-P., Juvela, L., Thuillier, E., & Välimäki, V. **"Deep Learning for Tube Amplifier Emulation."** *44th IEEE International Conference on Acoustics, Speech and Signal Processing (ICASSP 2019)*, Brighton, UK, pp. 471–475. Trains a feedforward WaveNet variant to regress against SPICE-simulated input/output pairs of a Fender Bassman 5F6-A tube amplifier circuit. [SigPort](https://sigport.org/documents/deep-learning-tube-amplifier-emulation) · [Aalto research portal](https://research.aalto.fi/en/publications/deep-learning-for-tube-amplifier-emulation) · [ResearchGate](https://www.researchgate.net/publication/332790880_Deep_Learning_for_Tube_Amplifier_Emulation) · [arXiv PDF](https://arxiv.org/pdf/1811.00334)

- Damskägg, E.-P., Juvela, L., & Välimäki, V. **"Real-Time Modeling of Audio Distortion Circuits with Deep Learning."** *Proceedings of the 16th Sound and Music Computing Conference (SMC 2019)*, Málaga, Spain, pp. 332–339. Generalizes the WaveNet regression approach from simulated data to real distortion pedals, with a real-time desktop implementation. [SMC2019 PDF](https://www.smc2019.uma.es/articles/S5/S5_02_SMC2019_paper.pdf) · [Aaltodoc](https://aaltodoc.aalto.fi/handle/123456789/38824) · [Zenodo](https://zenodo.org/records/3249374) · [Semantic Scholar](https://www.semanticscholar.org/paper/Real-Time-Modeling-of-Audio-Distortion-Circuits-Damsk%C3%A4gg-Juvela/89ee8b5acb9a52e2a953f39e791ac5313e189257)

### 3.2 Journal synthesis (Wright, Damskägg, Juvela, Välimäki)

- Wright, A., Damskägg, E.-P., Juvela, L., & Välimäki, V. **"Real-Time Guitar Amplifier Emulation with Deep Learning."** *Applied Sciences* (MDPI), 10(3), 766, 2020. Compares WaveNet and RNN black-box models across three distortion pedals (Ibanez Tube Screamer, Boss DS-1, Electro-Harmonix Big Muff Pi) and two valve amplifiers (Blackstar HT-5 Metal, Mesa Boogie 5:50 Plus); reports that roughly 3 minutes of training audio was sufficient. Open access. [MDPI](https://www.mdpi.com/2076-3417/10/3/766) · [Edinburgh Research Explorer](https://www.research.ed.ac.uk/en/publications/real-time-guitar-amplifier-emulation-with-deep-learning) · [Aalto research portal](https://research.aalto.fi/en/publications/real-time-guitar-amplifier-emulation-with-deep-learning) · [ResearchGate PDF](https://www.researchgate.net/publication/338723685_Real-Time_Guitar_Amplifier_Emulation_with_Deep_Learning)

### 3.3 RNN black-box modeling (Wright, Damskägg, Välimäki)

- Wright, A., Damskägg, E.-P., & Välimäki, V. **"Real-Time Black-Box Modelling with Recurrent Neural Networks."** *Proceedings of the 22nd International Conference on Digital Audio Effects (DAFx-19)*, Birmingham, UK, 2019. Compares LSTM and GRU architectures for tube-amp/distortion-pedal emulation; finds LSTM matches WaveNet-level accuracy at substantially lower compute cost; includes a real-time JUCE plugin implementation. This paper is the closest academic precedent to NAM's LSTM architecture option (Section 1.3). [DAFx paper archive](https://www.dafx.de/paper-archive/details.php?id=tieFMcaohHBxl_2yPyIGFA) · [PDF](https://dafx.de/paper-archive/2019/DAFx2019_paper_43.pdf) · [Aalto research portal](https://research.aalto.fi/en/publications/real-time-black-box-modelling-with-recurrent-neural-networks/)

### 3.4 Alec Wright's doctoral thesis

- Wright, A. **"Neural Modelling of Audio Effects."** Doctoral dissertation, Aalto University, 2023 (supervisor: V. Välimäki). Covers LFO-modulated time-varying effects, compressors, and guitar amps/distortion pedals; introduces a perceptual pre-emphasis filter and pruning techniques for model-size reduction, plus unpaired-data (adversarial) training approaches — directly relevant background for the "generalizes beyond guitar amps" framing and for the pre-emphasis-loss technique used in NAM (Section 2.3). [Aaltodoc](https://aaltodoc.aalto.fi/items/f376f16e-982a-485e-8412-1cb8362f9908) · [Aalto research portal](https://research.aalto.fi/en/publications/neural-modelling-of-audio-effects/) · [Edinburgh Research Explorer](https://www.research.ed.ac.uk/en/publications/neural-modelling-of-audio-effects/)

### 3.5 Steinmetz & Reiss on neural compressor modeling

- Steinmetz, C. J., & Reiss, J. D. **"Efficient Neural Networks for Real-Time Modeling of Analog Dynamic Range Compression."** *152nd Audio Engineering Society (AES) Convention*, 2022; also arXiv:2102.06200. Uses a sparse-dilation temporal convolutional network (TCN) to model an LA-2A-style compressor, real-time capable on CPU, trained on only 10 minutes of data. This is the confirmed real title/venue matching the paper referenced loosely in the research brief. [arXiv abstract](https://arxiv.org/abs/2102.06200) · [arXiv PDF](https://arxiv.org/pdf/2102.06200) · [AES E-Library](https://www.aes.org/e-lib/browse.cfm?elib=21709) · [project page](https://csteinmetz1.github.io/tcn-audio-effects/) · [code](https://github.com/csteinmetz1/micro-tcn)
- Related work from the same authors, useful if the paper wants to cite broader differentiable/neural-effects-modeling context: **"Style Transfer of Audio Effects with Differentiable Signal Processing"** (DeepAFx-ST), *Journal of the Audio Engineering Society*, Sept. 2022, arXiv:2207.08759 [project page](https://csteinmetz1.github.io/DeepAFx-ST/) · [code](https://github.com/adobe-research/DeepAFx-ST); and **"Steerable Discovery of Neural Audio Effects,"** arXiv:2112.02926 [project page](https://csteinmetz1.github.io/steerable-nafx/).

### 3.6 Does NAM cite this lineage directly?

No explicit "related work" or citation list naming Damskägg, Wright, or Välimäki was found in NAM's own GitHub README, wiki, or DeepWiki documentation — the README simply describes NAM as a "neural network emulator for guitar amplifiers" without inline academic citations [sdatkinson/neural-amp-modeler](https://github.com/sdatkinson/neural-amp-modeler). NAM's architecture documentation does trace its WaveNet variant to the original DeepMind WaveNet paper as the ultimate architectural ancestor [WaveNet Architecture | DeepWiki](https://deepwiki.com/sdatkinson/NeuralAmpModelerCore/2.3.1-wavenet-architecture), and Atkinson's own interview material describes NAM's origin as an independent personal side project rather than a direct continuation of the Aalto papers [TONE3000 interview](https://www.tone3000.com/blog/ai-guitar-tone-interview-neural-amp-modeler-inventor-steven-atkinson). However, the architectural approach — non-autoregressive feedforward WaveNet and LSTM black-box regression trained with ESR/pre-emphasis loss — is functionally the same lineage established by the Damskägg/Wright/Välimäki papers above, and NAM's own source code cites the Wright et al. perceptual-loss paper directly in its issue tracker when implementing ESR (Section 2.3). Secondary academic literature that cites NAM alongside this Aalto research line was also found during this research, reinforcing that outside observers treat NAM as part of the same lineage even though NAM's own documentation does not spell this out explicitly. **For the paper: it is accurate to describe NAM as architecturally descended from this line of research, but not accurate to claim NAM's own documentation explicitly credits it — this distinction is worth stating carefully.**

### 4.2 GuitarML project

Created by **Keith Bloemer**. Key repositories:
- **[GuitarML/Chameleon](https://github.com/GuitarML/Chameleon)** — a free/open-source plugin using the RTNeural inference engine to emulate three tones of a vintage amp head.
- **[GuitarML/Automated-GuitarAmpModelling](https://github.com/GuitarML/Automated-GuitarAmpModelling)** — GuitarML's training pipeline (a fork/derivative approach) used to train these neural models, including a Colab training script.
- **[GuitarML/Proteus](https://github.com/GuitarML/Proteus)** — "Guitar amp and pedal capture plugin using neural networks," the successor to GuitarML's earlier SmartAmp/SmartPedal plugins with substantially lower CPU use, using RTNeural for inference. Users record their own input/output pairs and train models via ML; a community "Proteus ToneLibrary" hosts shared captures.

Bloemer states his methods derive from Aalto University Acoustics Lab research on black-box neural modeling of guitar amps/effects [GuitarML FAQ, Keith Bloemer](https://keyth72.medium.com/guitarml-faq-6b18abc1116c) — i.e., the same academic lineage documented in Section 3, and closely related in approach to NAM (WaveNet/RNN-style black-box capture), though GuitarML is an independent, free, and fully open-source project rather than a commercial product.

### 4.3 Community capture-sharing platforms: ToneHunt / TONE3000

ToneHunt and TONE3000 are the same platform under different names and codebases. ToneHunt began as a community effort connected to the NAM Facebook community and was rebuilt and rebranded as **TONE3000** on May 6, 2024, moving from an open-source to a closed-source codebase while remaining free to use [Welcome to the New ToneHunt](https://www.tone3000.com/blog/welcome-to-the-new-tonehunt). TONE3000 describes itself as "the world's largest community-driven platform for sharing and discovering digital models of amps, pedals, outboard gear, full rigs," and explicitly states it was "built on the open-source project Neural Amp Modeler (NAM) by Steve Atkinson" [TONE3000 About](https://www.tone3000.com/about). The platform is not exclusively NAM captures — it also hosts impulse responses (IRs) and accepts uploads of either format.

Scale: reporting shortly after the TONE3000 relaunch cited more than 90,000 community-trained models within months (with 1.3 million downloads) [Show HN: TONE3000, Hacker News](https://news.ycombinator.com/item?id=44331497); more recent coverage cites a library exceeding 350,000 total tone captures [TONE3000 A2 architecture coverage, MusicTech](https://musictech.com/news/gear/tone3000-nam-architecture-a2/).

**Significance for the paper:** this scale of freely available, pre-trained community captures is precisely what makes NAM usable by musicians and producers who have no interest in or expertise with ML training — they can download a ready-made `.nam` model of a specific real-world amp, pedal, or full signal chain rather than performing their own reamping/training workflow. This is directly relevant to framing why a Csound opcode that loads `.nam` files (rather than one that trains them) is a practically useful integration: it lets Csound users draw on this large, pre-existing, free community library.

## 5. Prior Art: NAM (or Comparable Real-Time Neural Audio Inference) in Computer-Music Environments

*This is the section the paper's novelty claim depends on. Findings are reported plainly, including negative results, with the search queries used listed for transparency.*

### 5.1 Does NAM ship an official plugin, and in which formats?

Confirmed (also covered in Section 1.2): the official **[`sdatkinson/NeuralAmpModelerPlugin`](https://github.com/sdatkinson/NeuralAmpModelerPlugin)** repository ships **VST3 and AU (Audio Unit)** builds plus a standalone application, built with **iPlug2**. AAX, CLAP, Linux, and iOS are listed in the README as *possible future targets*, not currently shipped formats. **LV2** support exists only via a separate, third-party, community-maintained plugin ([`mikeoliphant/neural-amp-modeler-lv2`](https://github.com/mikeoliphant/neural-amp-modeler-lv2)), not the official project.

### 5.2 Csound integration — searched thoroughly, no prior art found

Extensive search queries were run against NAM/Csound integration, including (non-exhaustive list): "NAM csound", "neural amp modeler csound opcode", "csound neural amp modeler", "NeuralAmpModelerCore csound", "csound neural network real-time inference opcode", "csound WaveNet opcode", "csound guitar amp modeling", "csound machine learning opcode guitar amp", "csound .nam model", plus targeted `site:github.com` searches for "csound neural amp" and "NeuralAmpModelerCore." The official Csound opcode manual/reference and the Csound GitHub repository/issue tracker were also checked for any mention of "neural amp," "NAM," "WaveNet," or "RTNeural."

**No evidence of any prior Csound integration of NAM, NeuralAmpModelerCore, or a comparable real-time neural amp/effect inference engine was found.** No Csound opcode, plugin wrapper, or opcode-manual entry referencing NAM, NeuralAmpModelerCore, WaveNet-based amp modeling, or RTNeural-based amp modeling turned up in this search. No Csound mailing-list, forum, or community discussion thread proposing or requesting such an integration was found either. This supports — but on its own does not conclusively prove absence of — a "first native Csound opcode for NAM" novelty claim; the caveat is that private/unpublished efforts, very recent unindexed work, or work published after this research's cutoff cannot be ruled out by web search alone. **The paper should phrase the novelty claim carefully (e.g. "to the best of our knowledge, no prior published Csound integration exists") rather than as an absolute, unfalsifiable claim.**

### 5.3 Other computer-music environments — relevant prior art DOES exist here (important for related-work framing, even though it's not Csound)

Unlike Csound, other computer-music/DSP environments do have documented neural-amp-modeling integrations, which the paper should likely cite as related work / precedent for "this kind of thing is a natural direction," even though none of it is Csound-specific and therefore does not undercut a Csound-specific novelty claim. **Update 2026-07-03: an independent second research pass corroborated and sharpened this section with direct source verification (concrete repo URLs, author names, direct WebFetch of primary pages) — confidence upgraded from the original caveat below, now cite directly:**

- **Max/MSP — `neural_tilde`.** Open-source C++ Max external by GitHub user **apresta** (posts on the Cycling '74 forum as "spiritofeden"). Loads **NAM `.nam` files directly, as well as AIDA-X models**, runs them in real time, built on the `NeuralAudio` inference library plus `AudioDSPTools` for resampling. This is the single closest documented prior art to this paper's work — it uses the *same model format* (`.nam`) in a *different host environment* (Max, not Csound).
  - Repo: [github.com/apresta/neural_tilde](https://github.com/apresta/neural_tilde)
  - Announcement thread: [Cycling '74 forum](https://cycling74.com/forums/neural-amp-modeler-maxmsp-external)

- **SuperCollider — two separate projects, both by Sam Pluta.**
  - **"Proteus" UGen** — loads LSTM guitar-amp models in the **Proteus VST format** (GuitarML's format, *not* NAM's `.nam` format) via the RTNeural inference library. Author reports "2% CPU on a 40-layer LSTM" and notes he has also used NAM but has "no critical comparison of which is better." [scsynth.org thread](https://scsynth.org/t/proteus-neural-amp-modeling-ugen/9863)
  - **General-purpose RTNeural inference UGen** — wraps jatinchowdhury18's `RTNeural` library (Dense/GRU/LSTM/Conv1D/Conv2D/BatchNorm layers, loads PyTorch/TensorFlow-trained models). Per the announcement thread, this plugin family **"now runs on SuperCollider, Max/MSP, and Pure Data"** — i.e. a generic (non-amp-specific) real-time neural-inference UGen/external already spans three of the target environments. [scsynth.org thread](https://scsynth.org/t/rtneural-real-time-neural-inference-ugen/10074)

- **Pure Data.** No PD-specific NAM integration found. The RTNeural-based external above (cross-compiled for PD per its own announcement) is the closest thing — generic neural inference, not NAM/amp-specific.

- **ChucK / Faust.** No hits whatsoever for NAM or comparable neural amp modeling in either environment (checked as part of the corroborating pass).

- **A genuinely different prior Csound "amp opcode" exists, but it is non-neural** — worth citing explicitly to preempt a reviewer finding it first: Pekonen, Pakarinen et al., **"A Csound Opcode for a Triode Stage of a Vacuum Tube Amplifier,"** DAFx-11 ([IRCAM PDF](http://recherche.ircam.fr/pub/dafx11/Papers/42_e.pdf), [ResearchGate](https://www.researchgate.net/publication/255746938_A_Csound_opcode_for_a_triode_stage_of_a_vacuum_tube_amplifier)). This is a circuit/physical model of a single tube stage, not a data-driven neural model of a full amp — genuinely different technique, same instrument-modeling space. Good "related work, but importantly different" citation.
  - The general Csound third-party opcode ecosystems (`csound-plugins/csound-plugins`, `rorywalsh/csoundPluginOpcodes`) were also checked directly — no neural/ML amp-modeling opcode of any kind exists there either.

None of the neural-inference precedents above are Csound, and none were found to be built specifically on NAM's own `NeuralAmpModelerCore` C++ library — they use adjacent/generic real-time neural inference libraries (`NeuralAudio`, `RTNeural`) in the same architectural spirit, and in Proteus's case a different model format entirely. **This is useful related-work context**: it shows the general idea of "real-time neural amp/effect inference as a computer-music-language primitive" already has precedent elsewhere (Max/MSP, PD, SuperCollider), which both (a) validates that this is a reasonable, wanted kind of integration, and (b) leaves Csound specifically as a confirmed gap, supporting the paper's novelty claim for Csound while being honest that the *general concept* is not unprecedented.

**Confidence note:** Section 5.2's Csound-negative-result and this section's Max/MSP + SuperCollider findings have now been corroborated by two independent research passes (~18-19 distinct search queries each, overlapping but not identical, plus direct WebFetch of primary source pages in the second pass) reaching the same conclusion with mutually consistent, specific citations. Phrase the novelty claim in the paper as "to the best of our knowledge, no prior published Csound integration exists" (falsifiable-but-well-searched), not as an absolute claim — standard academic hedging, not a weakness given the search depth here.
