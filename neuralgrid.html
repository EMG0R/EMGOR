The Chain

G1

Interaction Space — the Physical Rig

top-down view · 4-sided symmetric tabletop · sensed 3 spatial + 1 temporal

The interface is defined by dimensional classes, not hardware. Any rig declaring the same sensor manifest — same classes, same arrangement — is compatible with the same trained model.

free-1D — dwell anywhere
sprung field — 4ch: blurry (x,y) + depth
2D-lattice — discrete grid
anchored-3D — known (x,y), read z

control-surface split: the playing surface is only for playing — no reserved softpot, all four are playable. Meta-controls (adaptation-rate, snapshot save / recall / morph) can live on a separate external USB control device — but it's optional, a gig convenience. The instrument is complete alone: the corner-pincer control layer (see § Direct Control) reaches every meta-control from the playing surface itself.

G2

The 12D State Manifold

a canonical lift, built from theorems — not a chosen list

A snapshot of the player is 3+1. A gesture is a curve through 3+1 — a higher-dimensional object. The extra dimensions are dimensions of the gesture, not the snapshot. Time is the ladder.

The Gesture, Seen Four Ways

NOW
xyz
where it is — raw sensing.
MOTION
ẋẏż
how it's moving — phase space (Hamilton): position alone doesn't determine the future; mechanics is only deterministic in (position, velocity).
MEMORY

where it just was — delay embedding (Takens 1981): plotting a signal against its own past provably reconstructs the hidden higher-dimensional dynamics of the system that generated it (the player's body / nervous system).
SHAPE

what it's drawing — path signatures (Chen / Lyons): level-2 signed areas; clockwise vs. counterclockwise circling, per plane; the signature characterizes the path.
t₁ · BEAT PHASE

t₂ · THE FAN
probability time — spreads, collapsed by the player's acts.

Two temporal companions ride alongside the 12 — not a fifth block, but the clock and the fan the blocks live inside.

Cover's theorem (1965): patterns inseparable in low dimension become separable when lifted. Two gestures identical as snapshots are far apart in the 12D lift.

velocities = one subtraction · delay coordinates = a ring buffer · signed areas = a running sum — all 12 dimensions cost microseconds.

G3

The DSP Graph — 10 Axes, 4 Families

spectrum · excitation · time · space

Harmonicity is the anchor axis, at two scales: within one note it reads as timbre; between notes it reads as harmony, where consonance is alignment with the harmonic series. Tuning is a runtime render table — never a trained dimension.

Example addresses (self-explanatory naming, illustrative, not calibrated):

  • 808 kick — harmonic, sparse, dark, struck, mild NL, continuous, dry, pitch-down motion, center, point
  • supersaw — harmonic-dense, saturated, bright, sustained, mild NL, continuous, smeared, audio-rate detune, wide, enveloping
  • granular cloud — inharmonic/noisy, variable density, mid tilt, sustained texture, low NL, grains, heavily smeared, audio-rate modulated, wide, enveloping

Training Mechanics

Five Locked Decisions

jazz, not just data collection

1 · LIVE RECURSIVE LOOP
the default mode. The model and the interface redesign themselves constantly, mid-performance — not between sessions. All changes land on downbeats.
2 · INFERRED TIME
tempo and downbeats are inferred from the player's own timing consistency (gesture onsets), not only an external clock. Rule: the model's timing consistency must match or exceed the player's — it leans toward consistency.
3 · SNAPSHOTS
“save as” freezes the current instrument-state; recall any snapshot later; morph between saved snapshots. A secondary interface exposes an adaptation-rate control — continuously slows or speeds the model's evolution, from frozen to full-speed.
4 · PREDICTION LOGGING
every tick logs predicted-vs-actual — what the model thought the player would do vs. what they did. This stream is both the training corpus and a real-time signal (tension / surprisal). Events are tagged by author: human vs. model.
5 · ARCHETYPES ARE REAL INSTRUMENTS
no boring data-collection instruments — every archetype must be worth playing for its own sake. Initial suite, timbrally diverse under one theme: a sampler-feel instrument, bells / gamelan (with gamelan tuning), a drum kit, a harmonic instrument. The list will grow.

Raw Start Profiles

PER-TARGET START POINT
the adaptation-rate dial doesn't start in the same place for every archetype — each target instrument carries its own session profile setting where the dial begins. The Machine Orchestra profile starts at zero: a fully raw, unadapted instrument. It ramps up over the course of the session, or by hand on the secondary interface — never pre-adapted before the player has touched it.

Training Ownership

SOLE TRAINER
only emgor's playing enters the corpus. The artifact is a mirror of one musician that others get to play — the method stays person-agnostic (anyone could train their own instance), the artifact is personally trained. When someone unlike the trainer plays it, surprisal runs visibly hot — the mirror shows them the difference. That's the concept, not a bug.
ARMED CAPTURE
training-logging is toggled deliberately — control layer, MODEL corner, a REC pad. Default off. Whenever armed, an unmistakable LED tell: a slow-breathing red pixel, so the instrument's learning state is never ambiguous. Chunked, low-priority writes to disk every few seconds — a power loss costs only the last seconds.
OVERNIGHT ON-PI TRAINING
the whole loop lives in the box: play, log, learn overnight — a 1–5M param model, several epochs a night on the Pi 5 (active cooling), never training while performing. The Mac is for experiments only — no cloud. Corpus v1 gate: ∼4 hours total, in 30–45 min sessions across days, ≥4 archetypes (gong / gamelan, drums, sampler, the common-tone harmonic instrument).

Corpus Strategy

MINIMUM VIABLE CORPUS, THEN LIFETIME ACCRETION. Bootstrap the predictor on the least data that beats baseline (∼2–4h) — then the corpus keeps accruing through ordinary armed use, for months.

CHAMPION / CHALLENGER
the model is forward-only — no time-travel, no recalling model versions from months ago. Retrain any time, between sessions or nightly; a challenger ships to live only if it beats the current champion on held-out data. Bad retrains never go live — quality ratchets one direction, and there's nothing to roll back to because nothing worse ever ships. (Performance snapshots for DJ mode are a separate, unrelated feature — save / recall / morph of instrument-states, not model versions — and stay exactly as documented above.)
QUALITY FILTERS
every corpus segment is scored — decision-density, rhythmic consistency, armed-intentionality, raw-session purity — and training weights segments by that score: the best playing teaches hardest. Recency-weighted, with slow, deliberate forgetting.
ANTI-ECHO-CHAMBER
periodic raw sessions — adaptation rate pinned at zero, tagged in the logs — keep the corpus anchored to uninfluenced playing, unshaped by the model's own prior suggestions.
CAPACITY BUMPS
when the corpus outgrows the current model, capacity bumps to a larger one. The corpus is forever — retrains, and re-sizes, are free.

Jazz Mode vs. DJ Mode

JAZZ MODE
full live exploration — the recursive loop runs free, the model adapts continuously, mid-performance.
DJ MODE
playing predefined instruments — snapshots recalled and played straight, or morphed between. Both modes are first-class.

Training Pyramid

Seven Stages, Seven Gates

an ascending staircase — each stage has a hard gate before the next

STAGE 0 · FOUNDATION
logging + sensor manifest + schema frozen. Gate: a session replays bit-perfect.
STAGE 1 · ARCHETYPES
build the suite. Gate: every DSP axis swept by ≥1 archetype, and each is genuinely fun to play — “you’d play it for its own sake.”
STAGE 2 · CORPUS
logging rides all real playing — jams, rehearsals, gigs all count, not just dedicated sessions. Silence is auto-segmented out; phrase-rests are kept as data, not discarded. Gate: prediction quality beats baseline on held-out material — not an hours quota.
STAGE 3 · PREDICTOR v1
overnight training. Gate: beats dumb baselines by a set margin on held-out sessions; inferred tempo within tolerance of the player's actual timing.
STAGE 4 · SHADOW
runs live, renders the fan, changes nothing. Gate: latency holds, and predictions feel sane to the player — explicitly a subjective human gate.
STAGE 5 · INFLUENCE
downbeat swaps live, rate control active. Gate: a full session, nothing feels broken, freeze always works.
STAGE 6 · TARGETS
artistic map → NEPTR OSC / Machine Orchestra MIDI. Gate: per-target sign-off.

RAW LOGS NEVER EXPIRE. Every future model retrains from the same corpus; only a sensor or schema change could invalidate it — hence Stage 0 freezes first.

THE PINNED 12D SPACE IS THE FIREWALL. The predictor and the artistic map meet only through it; retraining one never cascades into the other.

Ensemble

Playing With Others — the Common-Tone Engine

hand-coded, no ML — an early archetype, the suite's harmonic instrument

An improvising keyboardist moves through keys. The grid must always offer playable pitches, in real time, without ever surprising the player's own hand. There's no model here and nothing is trained — the engine is a fixed rule, running against a live estimate of the player's own harmony.

The engine listens only to you. It has no ears on the ensemble — other musicians' harmony reaches it only secondhand, through your choices: what you land on, hold, and return to.

1 · CONTEXT IN
the harmonic context is a decaying histogram of the player's own note choices — not ensemble MIDI, not a bus feed. What you land on, hold, and return to accumulates into the live harmony estimate. Other musicians' harmony reaches the system only through your ears and your choices — you are the harmonic sensor.
2 · RANKING
every pitch on the grid is scored on three axes: (a) common tone — overlap with the current context histogram; (b) harmonic-series alignment — low-integer ratios, the same harmonicity axis G3 uses between notes; (c) voice-leading distance — how far a re-voice would sit from the notes already held.

THE GOLDEN RULE. A held pad never re-pitches. Only unheld pads re-voice, and only on the downbeat. Common tones keep their pads. Your finger is never lied to.

4 · ANCHORS CASCADE
a held common tone becomes an anchor. The system serves the next ring of common tones around anchor ∩ context — key changes flow around the player's own pivots, never against them.
5 · LED GRAMMAR
bright = common tone · mid = consonant new tone · dim = tension tone · glow = anchor. The pad grid reads its own harmony back at the player before a finger lands.
6 · SELF KEY-CHANGE
the player can hold a tone and re-center the whole engine on it, at any moment — a self-initiated key change, not one waiting on the ensemble.
bright — common tone
mid — consonant new tone
dim — tension tone
glow ring — anchor

the model's later role: it steers engine parameters — density, tension amount, re-voicing speed — it never overrides the ranking math above.

↓

everything above is automatic. the player can also reach in and drive it directly.

Direct Control

Direct Control — Twelve Parameters, Two Tiers

everything hand-reachable, nothing that needs a menu to find

Twelve performance parameters are hard-controllable, in four families. They are always reachable — one tier for the flow of playing, one tier for deliberate control — never buried in a settings screen.

HARMONIC · SW corner
  • 1 · key center (live)
  • 2 · tension (consonant ↔ spicy offers)
  • 3 · pitch-bend a held note
  • 4 · tuning table (12-EDO / JI / gamelan)
TIME · NW corner
  • 5 · tempo
  • 6 · rhythmic consistency (loose ↔ machine-tight)
  • 7 · busyness
  • 8 · swing
MODEL · NE corner
  • 9 · adaptation rate (frozen ↔ full-speed)
  • 10 · adventurousness
  • 11 · snapshots (save / recall / morph)
  • REC · armed-capture toggle (default off)
SOUND · SE corner
  • 12 · any DSP axis, via AXIS-GRAB

Two Tiers

IN-FLOW · NO MODE. Softpot meaning is contextual: holding a pad → that softpot bends the held pad's pitch. Holding nothing → the softpot takes its ordinary menu role. Key re-center = hold a tone + a re-center gesture — there is no separate mode to enter.

CONTROL LAYER · THE CORNER PINCER. Press two adjacent FSR field-quadrants at once — say, west + south — and hold for ∼0.5s; an LED ripple confirms the press. The corner where those two quadrants meet (here, SW) opens its control family. Four corners, four families: SW harmonic, NW time, NE model, SE sound. The grid then becomes the control panel for that family — 10 pads light as the 10 DSP axes for AXIS-GRAB (a softpot rides whichever axis you grab, always through the perceptual axes, never raw synth parameters), other pads hold the snapshot shelf, softpots ride rate / tension / consistency / busyness. Release the pincer — instantly playing again.

deliberate, two-handed, off the playing flow: an unseasoned player never stumbles into it. The expert just memorizes four pinches.

Reference Implementation

Runs On Any Laptop — Zero Custom Hardware

the sensor manifest compiles commodity input just as readily as the rig

The dimensional classes don't care what they're sensed by. A laptop's own inputs satisfy the same sensor manifest: keyboard = 2D event lattice, trackpad = free-2D field with Force Touch standing in as the sprung −Z, time = time. Same 12D lift, same predictor, same DSP graph — out as MIDI / OSC to any softsynth.

The framework and the training system are general — like RAVE: anyone can train it and get their own result. The hardware prototype is the flagship instance, not a requirement. emgor is choosing to train his on himself.

all software is developed on the laptop build first; the hardware rig is a plug-in peripheral, not a dependency.
